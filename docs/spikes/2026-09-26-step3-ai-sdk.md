## What was proven (mock model)

**The call that works:**

```ts
import { APICallError, generateText, NoObjectGeneratedError, Output, RetryError } from 'ai';

await generateText({
  model,                                   // a LanguageModelV4/V3 OBJECT, never a string (see below)
  instructions: systemPrompt,              // `system` still works but is @deprecated in 7.x
  output: Output.object({ schema }),       // zod 4 schema; `Output` is exported by name
  maxRetries: 0,
  maxOutputTokens: 1500,
  reasoning: 'low',   // 'provider-default'|'none'|'minimal'|'low'|'medium'|'high'|'xhigh'
  abortSignal: AbortSignal.timeout(80_000),
  messages: [{ role: 'user', content: [
    { type: 'text', text },
    { type: 'file', mediaType: 'image/jpeg', data: { type: 'data', data: bytes } },
  ] }],
});
```

**The image part.** The plan's `{type: 'image', image: bytes, mediaType}` (`ImagePart`) is
**`@deprecated`** in `@ai-sdk/provider-utils` 5.0.49. It still works: it reaches the model as
`{type: 'file', mediaType: 'image/jpeg', data: {type: 'data', data}}`. But every call prints
`DeprecationWarning: AI SDK Warning: Deprecated: "image" content part`. T8 and T10 build the
`FilePart` shape directly. `data` also accepts bare bytes, a `Uint8Array` or a `Buffer`.

**What the model receives** (`LanguageModelV4CallOptions`, from `mock.doGenerateCalls[0]`):
- `instructions` become a leading `{role: 'system'}` message;
- `maxOutputTokens: 1500` and `reasoning: 'low'` are passed through;
- `responseFormat.type` is `'json'`, with the zod schema turned into JSON Schema.

**`MockLanguageModelV4` and `MockLanguageModelV3`** (from `ai/test`) are both accepted.
`generateText`'s `LanguageModel` type is `GlobalProviderModelId | LanguageModelV4 | V3 | V2`.
A V3 model also received `reasoning: 'low'`, with no warnings. **T8's `mock.ts` uses
`MockLanguageModelV4`.**

**Where T8 reads each value:**

| Value | Where |
|---|---|
| finish reason | `result.finishReason`: `'stop' \| 'length' \| 'content-filter' \| 'tool-calls' \| 'error' \| 'other'`. The provider's own string is `result.rawFinishReason` |
| reasoning tokens | `result.usage.outputTokenDetails.reasoningTokens` |
| cached input | `result.usage.inputTokenDetails.cacheReadTokens` (also `noCacheTokens`, `cacheWriteTokens`) |
| totals | `result.usage.inputTokens`, `outputTokens`, `totalTokens`. In 7.x `result.usage` is already the sum over all steps, and `result.totalUsage` is `@deprecated` |
| response headers | `result.response.headers` (`Record<string,string>`), for rate-limit headers on success |
| the parsed object | `result.output` |

A mock result's `usage` is V4-shaped:
`{inputTokens: {total, noCache, cacheRead, cacheWrite}, outputTokens: {total, text, reasoning}}`.

**Errors, all measured:**

| Case | What `generateText` does |
|---|---|
| `length` stop, truncated JSON | **rejects** with `NoObjectGeneratedError`. `.finishReason === 'length'`, `.usage` is set (reasoning tokens included), `.text` is the raw text, and `.cause` is a `JSONParseError` |
| `length` stop, JSON that happens to be complete | **resolves**, with `finishReason === 'length'` and a valid `output`. **`callModel` must check `finishReason === 'length'` itself** and fail with `length` (L42). Catching `NoObjectGeneratedError` isn't enough |
| `stop`, invalid JSON | rejects with `NoObjectGeneratedError`: `finishReason 'stop'`, `usage` set, `cause` `JSONParseError` |
| `stop`, JSON that fails the schema | rejects with `NoObjectGeneratedError`, `cause` `TypeValidationError` |
| 429 with `maxRetries: 0` | **one** `doGenerate` call, and it rejects with **the `APICallError` itself**, not a `RetryError`. It has `.statusCode === 429`, `.responseHeaders['retry-after'] === '7'` and `.isRetryable === true` |
| 401 | `APICallError`, `.statusCode === 401`, `.isRetryable === false` |
| 502 with the **default** `maxRetries` (2) | 3 calls over about 6 s, then `RetryError` (`reason: 'maxRetriesExceeded'`, `errors.length === 3`). This is why `maxRetries: 0` is required (L44) |
| `abortSignal: AbortSignal.timeout(n)` | rejects with a `DOMException`, `name === 'TimeoutError'` (not an `APICallError`). Map it to `timeout` |

`generateText` also takes a `timeout` option (`TimeoutConfiguration`: a number of milliseconds,
or `{totalMs, stepMs, …}`). `abortSignal` was the one tested.

## What this means for T8 and T10

- **Always pass a model object from a `create*()` factory, never a string ID.** A plain string is
  a `GlobalProviderModelId`, which `ai` routes to the Vercel AI Gateway (`@ai-sdk/gateway` is a
  dependency of `ai`). Add this to `no-direct-calls.test.ts`, or give `callModel` a type that
  refuses `string`.
- **Never log an `APICallError` whole.**
  - `APICallError.requestBodyValues` is the whole request body: the prompt text and the base64
    image.
  - Log `statusCode`, `isRetryable`, the `retry-after`/rate-limit headers and a trimmed
    `message`.
  - `llm_calls.response` never stores `requestBodyValues`.
  - Extend pino's redaction to `err.requestBodyValues` and `err.responseBody`.
- **Silence the SDK's console warnings.** It logs warnings to the console by default (the "AI SDK
  Warning System" message above). Set `globalThis.AI_SDK_LOG_WARNINGS = false`, or assign a
  function that forwards to pino. The type is `LogWarningsFunction | undefined | false`.
- **Add `@ai-sdk/provider@4.0.18` as a devDependency.** `mock.ts` types the mock's `doGenerate`
  results with `LanguageModelV4GenerateResult` from `@ai-sdk/provider`, and pnpm doesn't resolve
  it through `ai` (TS2307).
- **Build `retry-after` from `APICallError.responseHeaders`** on errors, and from
  `result.response.headers` on success.

**Provider factory names**, read from each `dist/index.d.ts`. T8's plan text needs one fix:
- `createOpenAI({apiKey, baseURL, fetch, headers, organization, project, name})`
- `createAnthropic({apiKey, authToken, baseURL, fetch, headers, name})`
- **`createGoogle`** `({apiKey, baseURL, fetch, headers, name})`. The plan's
  `createGoogleGenerativeAI` still exists, but only as an alias
  (`export { createGoogle as createGoogleGenerativeAI }`).
- `createOpenAICompatible({name, baseURL, apiKey?, headers?, queryParams?, fetch?, includeUsage?, supportsStructuredOutputs?, transformRequestBody?, …})`.
  `name` and `baseURL` are required.

### 3. Findings that change T8, T9 and T10

1. **Send a portable "wire" JSON Schema; validate with the full zod schema afterwards.** What
   the AI SDK sends for `EXTRACTION_SCHEMAS` (checked with `asSchema(...).jsonSchema`):
   - the `bbox`/`document_bbox` tuples become draft-07 `items: [ … ]` arrays, which the
     XGrammar-based provider rejected;
   - `z.iso.date()` becomes `format: date` plus a ~300-character leap-year regex;
   - `aliases` becomes `propertyNames` plus `additionalProperties: {schema}`;
   - optional fields are left out of `required`, which Groq's strict mode rejects. By OpenAI's
     documented strict-mode rules, OpenAI's strict mode would too (inferred, not called).

   **T10 should derive a wire schema per mode:**
   - `bbox` as `{type: array, items: {type: number}, minItems: 4, maxItems: 4}`;
   - dates as plain strings described "YYYY-MM-DD";
   - `aliases` kept as an object (it worked on Groq with strict off).

   Pass it as `Output.object({schema: jsonSchema(wire)})`. **This also fixes a bigger problem:**
   with the zod schema, `Output.object` validates the whole answer, and one bad optional field
   throws `NoObjectGeneratedError` and loses everything (checked offline in
   `lenient-output.spike.ts`: `unit: "kms"` lost the whole reading). With `jsonSchema(wire)`,
   the raw object comes back, and `parseLenient` drops only `unit` (L52, as designed).
2. **Structured-output mode per provider:** `json_schema` with **strict off**, for both named
   kinds.
   - Groq: `providerOptions: {groq: {strictJsonSchema: false}}`.
   - OpenRouter: the model setting `structuredOutputs: {strict: false}`. The request shape was
     verified offline; this was not tested live.
   - **Never JSON mode** (`json_object`): it drops the schema.
   - An `openai_compatible` provider (`supportsStructuredOutputs: false`) would need the schema
     written into the prompt. Ollama is still untested.
3. **Reasoning on OpenRouter.** `@openrouter/ai-sdk-provider` 3.1.0 **silently ignores
   `generateText`'s `reasoning` option**: it never reads it, and returns no warning. Verified
   offline in `wire-shapes.spike.ts`, where the request body had no `reasoning` field.
   `providers.ts` must pass it as the model setting:
   `createOpenRouter(...)(id, {reasoning: {effort}, usage: {include: true}, structuredOutputs: {strict: false}})`.
   `@ai-sdk/groq` maps `reasoning: 'low'` to `reasoning_effort: "low"` correctly.
4. **Confidence is not calibrated for readings.** The same odometer image gave `0.04340057` and
   `52340`, both at 0.98. This supports D19 (a reading always waits for review) and D129. The
   READING prompt should state that the value is an integer count of the unit shown. `checks.ts`
   could flag a fractional odometer value; a hard reject needs a decision, because hour meters
   can be fractional.
5. **Model and serial need LABEL mode.** THING mode left out a clearly printed model code and
   serial; LABEL mode got both exactly. T10 or T26 should route nameplate photos to LABEL.
   `apply.ts` should treat a THING answer without a serial as "not read", not as "none".
6. **Hallucinated optional fields.** The model filled `warranty_terms_printed` with invented
   text at confidence 0, and gave a confident wrong Arabic address. `checks.ts` should drop any
   field below `CONFIDENCE_MIN` before apply (not just queue it for review), and the vendor
   address waits for review as §7.8 already says.
7. **Errors inside a 200.** OpenRouter can return `{error}` in an HTTP 200 body, and the package
   raises `APICallError` with `statusCode: 200`. `call.ts` should map `APICallError` with
   status < 400 to `provider_error`, retryable.
8. **429s with no headers.** OpenRouter's upstream 429s carry no `retry-after` and no rate-limit
   headers. The breaker's 60 s default applies. A `:free` model should not be offered at all.

### 4. Pacing numbers

**Groq's headers** on every response (this key's tier):
- `x-ratelimit-limit-tokens: 8000`, a per-minute window;
- `x-ratelimit-limit-requests: 1000`. Inferred to be per day: `x-ratelimit-reset-requests`
  grew by about 86 s per request (86 400 / 1000).
- `x-ratelimit-remaining-tokens`;
- `x-ratelimit-reset-tokens` (e.g. `21.037s`) and `x-ratelimit-reset-requests` (`1m26.4s`, a Go
  duration string).

**How many tokens a call costs against the limit.** After the first receipt, the remaining
tokens were 8000 − 2805:
- the 2805 fits 585 output tokens plus ~2220 input;
- the ~2220 fits Groq's documented flat **2048 tokens per image** plus ~172 prompt tokens
  (inferred), even though the reported usage was 1917 input tokens.

So **one extraction costs ~2.2k–2.8k tokens against the limit, and about 2–3 extractions per
minute fit** on this tier.

**What T8 needs for Groq:**
- `estimateImageTokens` for `groq` returns 2048 per image (Groq's documented figure; it also
  matches what was observed).
- The pacer reads `x-ratelimit-remaining-tokens` and `x-ratelimit-reset-tokens` on success, and
  pauses before the provider does. `DEFAULT_BUDGETS.extraction.tokensPerMinute` (60 000) is
  7.5× this tier, so Kept's own budget will not protect it.
- Keep Groq extractions to **one image per request, one at a time**
  (`concurrency: 1` for `groq`).

**Output caps.** Reasoning used 91–293 tokens, and no call came near its cap: the largest output
was 685 of 4548. `REASONING_ALLOWANCE.low = 2048` is ample here; no `length` stop was seen.

**OpenRouter:** no rate-limit headers were seen, and `GET /api/v1/key`'s `rate_limit` field says
it is deprecated.

### 6. Key prefixes (D202 `detectKind`)

These are observed on the maintainer's keys (only the prefix and shape were checked; nothing was
