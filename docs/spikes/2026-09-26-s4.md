# Spike S4 (V16): shadcn's React Aria base

Date: 2026-09-26. Result: **installs cleanly and mirrors correctly in RTL, but it is a starting
point, not a drop-in.** Kept keeps shadcn's aria-base component structure and rewrites every
primitive in place on `react-aria-components`, with Kept's tokens, the screens kit's sizes and
Lingui strings. The toast is the one real fallback: it is written directly on React Aria's toast
queue, because the aria base ships `sonner`.

## What was run (shadcn 4.21.0, looked up with `npm view shadcn`)

Flags come from `shadcn init --help` and `shadcn add --help`. The preset key (`nova`) comes from
the preset table in the CLI's own `dist/index.js`, because `init` otherwise stops at an
interactive preset prompt.

```sh
npx shadcn@4.21.0 init -t vite -b aria -p nova --rtl -n spike --no-monorepo -y
npx shadcn@4.21.0 add input field dialog combobox switch sonner card tabs direction -y -o
```

This produced a Vite app with `components.json` `"style": "aria-nova"`, `"rtl": true`, and the
components in `src/components/ui/`, all built on `react-aria-components` 1.21.1.

## What was proven

- **The base is real React Aria.** Button, Input, Dialog (`ModalOverlay` + `Modal` + `Dialog`),
  ComboBox (`ComboBox` + `Popover` + `ListBox`), Switch and Tabs are the React Aria components with
  classes on top. Keyboard, focus, ARIA wiring and i18n behaviour are React Aria's.
- **RTL is handled.** The classes use logical utilities (`ps-`, `pe-`, `start-`, `end-`), with
  `rtl:` overrides only for transforms. Direction comes from React Aria's `I18nProvider`, which
  shadcn wraps as `DirectionProvider`. With `locale="ar"`, React Aria mirrors arrow-key handling
  itself: in Tabs, ArrowLeft moves to the next tab. Kept's test `tabs.test.tsx` checks this.

## Why it isn't used as generated

- **Toast isn't React Aria.** The aria base's toast is `sonner`, and its wrapper imports
  `next-themes`. shadcn's own registry says the `toast` component is for the Base UI base only.
  Kept writes the toast on React Aria's `UNSTABLE_ToastQueue` / `UNSTABLE_ToastRegion` /
  `UNSTABLE_Toast` (`apps/web/src/components/ui/toast.tsx`). **Risk:** those exports are still
  `UNSTABLE_` in 1.21.1, so check them on every React Aria upgrade.
- **The strings aren't translatable.** The generated code hard-codes English accessible names
  (the dialog's `Close`, the combobox's `Clear`). Kept's versions take them from Lingui.
- **It targets shadcn's theme, not Kept's.** The classes use `--primary`, `--popover` and
  `--muted`, and the controls are 32 px tall (`h-8`). The screens kit wants 40 px buttons and
  44 px inputs and touch targets (`docs/design/screens/kit.css`), coloured with the board's tokens
  (D131).
- **Extra runtime dependencies.** `shadcn` itself (for `shadcn/tailwind.css`, which is mostly
  custom variants for Radix and Base UI `data-state` attributes), plus `class-variance-authority`,
  `lucide-react`, `tw-animate-css`, `sonner` and `next-themes`. Kept needs none of them. Its only
  addition is `cn` 0.4.0, the shadcn-maintained class merger that the aria base imports. Kept
  registers the D132 type-scale names with it (`createCn`) so that, for example, `text-small`
  isn't merged away as a colour.
- **No PasswordField.** The registry doesn't have one; Kept composes it from React Aria's
  `TextField`, `Group` and `Button`.

## The exact config Kept keeps

- `apps/web/components.json` records the base (`aria-nova`, `rtl: true`, aliases `@/components`
  and `@/lib/utils`). Later tasks can read a new component's source with
  `npx shadcn@4.21.0 add <name> --view` (or `--dry-run`), then restyle it the same way.
  **Don't run a plain `add`:** it writes shadcn's CSS variables into `src/styles/index.css` and
  adds the dependencies above with `^` ranges.
- The primitives are in `apps/web/src/components/ui/`: `button`, `text-field`, `password-field`,
  `dialog` (`Modal`, `Dialog`, `DialogTrigger`, `DialogFooter`), `combobox`, `switch`, `toast`
  (`toast()`, `<Toaster/>`), `confirm` (`useConfirm()`, `<ConfirmProvider/>`), `card` and `tabs`.
  Each has a Vitest and Testing Library test covering render, keyboard operation, and Arabic/RTL
  rendering with only logical utilities.

## Fallback taken

Partial. Toast is written directly on React Aria (not shadcn's `sonner`). Every other primitive
keeps the aria base's structure but is rewritten in Kept's styles. This is recorded in the §19 V16
row of the product design.
