# Spike R3: the image (size, the trim, the notices sources, the Ollama pin)

Date: 2026-10-06. Step-8 plan, Task 0a (it feeds T15 and the step-1 carry-over "the image ships
better-auth's optional peers"). Result: **PASS with a different trim than the plan proposed.**
- **The workspace settings the plan named don't trim anything.** `resolvePeersFromWorkspaceRoot:
  false`, `dedupePeerDependents: false`, a pnpm `overrides` entry removing the peers (`'-'`) and a
  `packageExtensions` narrowing each left better-auth 1.7.6 resolved **with** `vitest` and
  `drizzle-kit` in the lockfile (pnpm 11.23.0, fresh `--lockfile-only` resolves).
- **What works: a prune after `pnpm install --prod`** (`docs/spikes/code/step8/image/prune-optional-peers.mjs`):
  walk the pnpm store from the shipped packages, don't follow better-auth → vitest/drizzle-kit,
  delete what the walk never reached. **85 store entries, 90.9 MiB** (vitest, vite, rolldown, jsdom,
  esbuild ×3, drizzle-kit, lightningcss, tsx, …). arm64 image **656 MB → 561 MB** (−95 MB,
  −14.5 %). `scripts/smoke-image.sh` **passes** on the pruned image. better-auth imports vitest
  only from `dist/test-utils/test-instance.mjs`, which Kept never loads.
- Two more trims found, **not yet tried** (T15 measures): drizzle's `migrations/meta/*_snapshot.json`
  are **26 MB** of the 28 MB migrations folder and drizzle's migrator reads only
  `meta/_journal.json` and the `.sql` files; npm + yarn + corepack in the Node base are ~25 MB the
  runtime never runs.
- **Multi-arch:** amd64 165.2 MB, arm64 141.3 MB compressed (pruned, pushed by digest in the
  [release spike](2026-10-06-step8-release.md)). The amd64 half spends **13 minutes** under
  emulation in the build stage alone.
- **Ollama for the Compose profile:** `ollama/ollama:0.35.1@sha256:292ee7945dfc3d5840a181f3ab86fedb1e66703e02c8af98b50f4da56b7e278c`,
  MIT; 3.8 GB (amd64) and 2.8 GB (arm64) compressed.

## The trim: what was tried

All in a scratch worktree, each from a fresh `pnpm install --lockfile-only` (lockfile deleted
first), reading the resolved `better-auth` entry of `apps/server` in `pnpm-lock.yaml`:

| Change in `pnpm-workspace.yaml` / `package.json` | better-auth's resolved peers |
|---|---|
| none (today) | `drizzle-kit`, `drizzle-orm`, `pg`, `react-dom`, `react`, **`vitest`** |
| `resolvePeersFromWorkspaceRoot: false` | unchanged |
| + `dedupePeerDependents: false` | unchanged |
| + root `devDependencies.vitest` removed | unchanged |
| `overrides: {better-auth>vitest: '-', better-auth>drizzle-kit: '-'}` | unchanged |
| `peerDependencyRules.ignoreMissing` + `packageExtensions` narrowing the two peers to `0.0.0-never` | unchanged |

pnpm's docs (`pnpm.io/settings/peer-dependencies`, `…/dependency-resolution`, read 2026-10-06)
describe each setting; why none of them changes an *optional* peer that the workspace has installed
was not established (not inferred either: recorded as observed). `apps/server` itself has
`drizzle-kit` as a devDependency, and `apps/web` has `vitest`.

**So the prune.** `prune-optional-peers.mjs` (run in the `prod-deps` stage right after `pnpm install
--prod`; its header explains it): roots are the store entries linked from `apps/server`,
`packages/shared` and `packages/mcp`'s `node_modules`; the walk follows each entry's own
`node_modules` symlinks except better-auth (and `@better-auth/*`) → `vitest`/`drizzle-kit`; every
unreached store entry is deleted, then the dangling symlinks. Dry run on today's image: 340 entries,
255 reachable, 85 dropped, 90.9 MiB. The full list is in the script's dry-run output; it is entirely
test and build tooling (vitest, `@vitest/*`, vite, rolldown, esbuild 0.18/0.25/0.28, tsx, jsdom and
its CSS/HTML parsers, drizzle-kit, lightningcss, postcss, `@types/*`, chai).

The two Dockerfile lines the spike added to `prod-deps` (T15 writes the real ones):

```dockerfile
COPY prune-optional-peers.mjs /tmp/prune-optional-peers.mjs
RUN node /tmp/prune-optional-peers.mjs /src > /tmp/pruned.json
```

## `pnpm licenses list --prod` against the image

`pnpm licenses list --prod --json --filter '@kept/server...'` (run on the laptop) lists 339
packages. Against the store entries actually in each image:
- **Platform binaries differ:** the laptop's list has the darwin-arm64 builds (`@img/sharp-darwin-arm64`,
  `@esbuild/darwin-arm64`, `@rolldown/binding-darwin-arm64`, `lightningcss-darwin-arm64`,
  `@myriaddreamin/typst-ts-node-compiler-darwin-arm64`, `fsevents`, …); the image has the
  `linux-arm64` ones (and `linux-x64` on amd64). Same licences, different packages.
- `has-flag` is in the image but not in the list.
- After the prune, **83 listed packages are not in the image** (the pruned tooling).
- **Conclusion for T15:** the third-party notices are generated **from the image's own
  `node_modules/.pnpm`** (each entry's `package.json` `license` and its `LICENSE*` file), per
  architecture, not from `pnpm licenses list`. The licence check (`scripts/check-licences.mjs`)
  should read the same set.
- Licences that need care, in the shipped set: **`web-push` MPL-2.0** (file-level copyleft: the
  notice and where its source is), **`@img/sharp-libvips-linux-*` LGPL-3.0-or-later** (a shared
  library loaded at run time: the notice and the libvips source pointer). `lightningcss` (MPL-2.0)
  is pruned.

## Build time under emulation

The multi-arch build in the release spike (warm pnpm store) took 15 min 16 s; the amd64 half's
`build` stage spent **486 s compiling and 278 s installing** under QEMU. The `build` stage's output
(server `dist`, web `dist`, the converted fonts) is architecture-independent JavaScript, CSS and
TTF, so **`FROM --platform=$BUILDPLATFORM … AS build`** should remove most of that (proposal,
**not tried**). `prod-deps` must stay on the target platform (it installs `sharp`'s and Typst's
per-arch binaries), unless pnpm's `supportedArchitectures` can select them from the build platform
(not tried).
