# Spike S3 (V14): managed accounts

Date: 2026-09-26. Result: **proven, no fallback needed.** Better Auth 1.7.6 accepts a synthetic
`.invalid` email, and managed accounts sign in by username. The one-time reset code is Kept's own
code, built on Better Auth's internal adapter.

## What was proven (`apps/server/src/auth/managed.test.ts`)

- **Synthetic email.** `auth.api.createUser` (admin plugin), called server-side with no headers,
  accepts `<uuid>@managed.invalid`. Its `z.email()` check passes, and no admin session is needed
  when there are no request headers. The username plugin's create hook validates the username,
  lower-cases it into `username`, and keeps the typed form in `displayUsername`.
- **Username sign-in.** `auth.api.signInUsername({ body: { username, password } })` works, and
  the match ignores case.
- **Unique usernames.** A second account with the same username, in any case, is refused with
  `USERNAME_IS_ALREADY_TAKEN`. The `auth."user".username` column is also `UNIQUE`.
- **No magic link.** Kept's `sendMagicLink` refuses any `.invalid` address with
  `400 EMAIL_UNDELIVERABLE` before anything is mailed. The `kept-security` plugin also refuses
  `.invalid` addresses on `/sign-up/email` and `/change-email`, so a person can't make an account
  that looks managed (D176). Only the server-side admin path creates them.
- **Admin reset code (D164).**
  - `issueResetCode(auth, userId)` returns 8 characters of Crockford base32 (no I, L, O or U).
    It stores only an HMAC-SHA256 of the code, keyed by `KEPT_AUTH_SECRET` and bound to the user
    id. It goes in Better Auth's `verification` table as `managed-reset:<userId>`, expires after
    30 minutes, replaces any earlier code, and signs out all the account's sessions.
  - `redeemResetCode(auth, authPool, { username, code, newPassword, ip })` checks the code in
    constant time, consumes it atomically, sets the password, and signs out every session,
    including any made between issue and redeem. It works exactly once. It fails once the code
    has expired or been replaced.
  - Wrong codes count against the account + IP limiter from S2 (kind `reset-code`), so guesses
    are delayed. They don't burn the code, so a stranger can't cancel someone's reset.

## Exact API used (names from `@better-auth/core/dist/types/context.d.mts`)

- `const ctx = await auth.$context` gives the `AuthContext`:
  - `ctx.internalAdapter.createVerificationValue({ identifier, value, expiresAt })`,
    `findVerificationValue(identifier)`, `deleteVerificationByIdentifier(identifier)`, and
    `consumeVerificationValue(identifier)`, which is atomic: the first caller gets the row, and
    later or expired calls get `null`.
  - `ctx.internalAdapter.findCredentialAccount(userId)`, `updatePassword(userId, hash)` (updates
    the credential account), `linkAccount({ providerId: 'credential', accountId: userId, userId,
    password: hash })`, and `deleteUserSessions(userId)`.
  - `ctx.password.hash(pw)` and `ctx.password.config.{minPasswordLength,maxPasswordLength}`
    (8 and 128 by default).
  - `ctx.adapter.findOne({ model: 'user', where: [{ field: 'username', value }] })` to find a
    user by username. The internal adapter has no username lookup.
  - `ctx.secret` is the configured `secret`.
- `auth.api.setPassword` wasn't used. It needs the user's own session, and here the redeemer
  isn't signed in.
