# Step 3 performance: snapshot, sync batch, inbox, CSV import and moves

Step 3, task 32 part B. Measured on 2026-09-29 between 22:20 and 23:30 (Cairo, EEST), and once more
inside the final gate run at 00:11 on 2026-09-30. It answers the plan's "Perf" item and the carry-over's
re-measures (T12's snapshot, T18's CSV import, `things/move.test`'s 200 things).

**Verdict.**
- The offline snapshot of 10,000 things meets the laptop gate (600 ms) and the 2 GB-floor budget
  (2 s) on the gate pass, where Postgres is limited to 1 CPU and 1 GB. **It misses 2 s on the
  slower-core proxy** (Postgres at 0.3 CPU, node on the efficiency cores): p95 2.0–2.7 s. A run
  on a real 2 GB, 2-vCPU VM (V5, D209) is still due before 1.0 and decides it.
- The 50-op sync batch (p95 about 0.9–1.1 s) and the inbox page at 500 open items (p95 about
  20 ms) have no §3.1 target. Their provisional limits are now set from these numbers.
- A CSV import works about 63–68 rows a second, 3 s for a 200-row chunk, 11 times faster than
  the 34 s a chunk measured under load in T18.
- Moving 200 things in one request stays well under 1 s: the whole test, setup included, takes
  about 330–345 ms.

## 3. T18's CSV import rate

The new third case in `step3.perf.test.ts`: a run of `CHUNK` = 200 rows through the front door
(create, dry run, start), then one `importChunk` timed, as the import job works it, in one
transaction. Each row has a two-level place path (10 rooms × 4 shelves, created on first use), a
quantity, a date, a price and shop (so a purchase), a brand, two tags and a legacy code. One
warm-up chunk, then 3 timed chunks, each its own run.

**2.96–3.53 s a chunk, 62.6–67.5 rows a second.** T18 recorded about 34 s a chunk under load
(10 queries a row); on this machine, not under load, it is about 11 times faster. The rows here
are richer than most spreadsheets (every optional column filled), so a plain name-and-place
import runs faster. At this rate the 10,000-row maximum (Q18) takes about 2.5 minutes.

## 4. `things/move.test`: 200 things in under 1 s

`vitest run src/things/move.test.ts -t "200 things in one request"`, three runs: **passed each
time; the whole test took 344, 334 and 329 ms**, including creating the place and inserting the
200 things. The move itself is timed inside the test and asserted under 1,000 ms; it is less
than those totals. It took 2.1 s under load on 2026-09-29. Load average 4.6–6.1.
