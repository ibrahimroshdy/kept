# UI audit, 2026-09-29 (step 3, T31b)

The first UI audit (master plan, "UI audits"): the app checked against itself, the screens spec
and the design board at the end of build step 3. Every high and medium finding is fixed; the lows
were carried to [step-3-carryover.md](../plans/step-3-carryover.md) and are fixed too (the phone
pass, 2026-09-30).

**Result: 1 high, 10 medium, 11 low.** All 11 high and medium are fixed in `apps/web`.

## How it was run

- **Build:** `e712c81` for the audit and the fix commits below for the re-run, built with `pnpm --filter '@kept/server...' build && pnpm --filter @kept/web build` in a
  separate worktree, served by `node --conditions=kept-dist apps/web/e2e/serve.mjs audit 8391
  --seed` (the `households` seed). Demo mode (`vite preview --outDir dist-demo`, `?demo=owner`,
  `firstrun`, `member`, `setup`, `signedout`) for the states the seed doesn't have: a full inbox,
  AI usage with calls, the paused-AI banner, first run, setup and sign-in.
- **People:** Ibrahim (owner, instance admin, English), Alfred (member, Arabic, his own
  بيت العائلة), Talia (viewer).
- **Screenshots:** every route found by following links from Home (46 route patterns for Ibrahim,
  34 for Alfred, 32 for Talia, plus `/l/<code>`, an unknown label, `/types/<id>`, a container,
  box check, a search, `/settings/me/ai` and a missing page) at **375 and 1280**, and **768** for 18
  representative routes (Home, Capture, Inbox, Search, Scan, Labels, a thing, a container, a
  location, a place, Settings, AI settings and usage, Import, Templates, Help, Activity, Admin):
  English light and dark, Arabic light, Arabic dark (the 768 subset), and the viewer. About 590
  JPEGs. They are working files, not in the repo: a `ui-audit/` folder in the session scratchpad,
  outside the repository (below: `ui-audit/`). `before/<variant>/` is the audit, `<variant>/` the
  re-run after the fixes, `demo/` the demo-mode states; files are `<route>-<width>.jpg`.
- **axe:** `@axe-core/playwright` 4.13.0 (MPL-2.0, on the dev licence list), tags WCAG 2.0/2.1/2.2
  A and AA plus best practices, on every screenshot. It was not wired in before (T30 left it
  open); it is now `apps/web/e2e/audit.spec.ts` (c7b830d): axe on every route an owner reaches
  from Home and on a member's Arabic pages, nothing above minor, on both projects.
- **Probes on every page:** horizontal overflow, text cut with an ellipsis or a line clamp, Latin
  text left in Arabic, touch targets under 44 × 44 px on the phone, console errors.
- **Keyboard walk** (also in `audit.spec.ts`, desktop): Capture from the top bar → shutter → Done →
  the Inbox from the sidebar → `j`, `e`, type a name, Save → ⌘K, arrows, Enter → the thing; and
  Labels → "Label everything unprinted" → start cell 3 with the arrow keys → Print → "Printed OK?"
  → Yes. Both pass with no mouse.
- **Navigation:** ⌘K, the rail (D198) at 768 and by `⌘\`, tooltips on keyboard focus, Back with a
  sheet open, deep links by short ID and by a lower-case, dashed ID (`/t/7kq-4mz`).

## What passed as it was

- **axe:** nothing above minor on any signed-in route in either theme or language, apart from the
  landmark and heading findings below (M7, M8). Colour contrast passed in light and dark.
- **Phones:** no horizontal scroll on any route at 375; no text cut with … anywhere.
- **The rail (D198):** 768 starts on the rail, 1280 expanded; `⌘\` toggles it; a rail icon shows
  its name in a tooltip on keyboard focus; the search icon opens the palette.
- **⌘K** opens with focus in the field, Escape closes it; deep links by short ID resolve and
  normalise (`/t/7kq-4mz` → `/t/7KQ4MZ`); an unknown label says "Not in your Kept".
- **Reduced motion:** with `prefers-reduced-motion: reduce`, no element has a running animation or
  transition (the sidebar's width transition is 0 s).
- **RTL:** Arabic mirrors, codes stay in Western digits and left to right (D143), the breadcrumb
  chevrons point the reading way, the capture strip mirrors.
- **Empty states** (Inbox, Templates, Paperwork, Links, AI usage) and the capture summary read in
  the D86 voice: short, plain, what happens next.
