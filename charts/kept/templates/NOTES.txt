Kept {{ .Chart.AppVersion }} is installed as "{{ .Release.Name }}" in namespace "{{ .Release.Namespace }}".
It answers at {{ .Values.publicUrl }}{{ if not .Values.ingress.enabled }} once you route it there (the Service is {{ $full }}:{{ .Values.service.port }}){{ end }}.

1. The first-run setup code. The first boot prints it once:

     kubectl -n {{ .Release.Namespace }} logs deploy/{{ $web }} | grep 'KEPT SETUP CODE'

   Lost it? Re-issue it while setup is pending. `kept admin` commands need the owner login,
   which the {{ $jobs }} pod holds only while backup.enabled is true{{ if not .Values.backup.enabled }} (it is false here){{ end }}:

     kubectl -n {{ .Release.Namespace }} exec deploy/{{ $jobs }} -- kept admin setup-code

2. The recovery kit: the keys, the backup repository and its password, the restore steps. Keep it
   off this cluster, the day you set Kept up and after every key or backup change:

     kubectl -n {{ .Release.Namespace }} exec deploy/{{ $jobs }} -- kept admin recovery-kit > kept-recovery-kit.txt
{{- if not .Values.keys.existingSecret }}

   The keys were generated into the {{ $full }}-config volume (D193). Without them, or the kit,
   every stored secret is unreadable.
{{- end }}
